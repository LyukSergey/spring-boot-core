> **Тип:** практичне заняття (3 пари, 6 годин).
> **Максимальний бал:** **25**.
> **Повна інструкція з реалізації:** див. [`pz-2-pdf.md`](./pz-2-pdf.md).
> Цей файл — лише **умова** й **бали**.
>
> ⚠️ **Це НЕЗАЛЕЖНЕ завдання** — воно НЕ продовжує ПЗ-1. Новий проєкт з нуля.

## Легенда

Ти робиш сервіс для невеликої компанії. Раз на місяць (і за запитом) він має формувати
**красивий PDF-звіт про продажі** та розсилати його керівникам на email. Дані про продажі
беруться з **REST API, який ти ж і надаєш** (менеджери додають продажі через нього).

## Умова — що потрібно зробити

1. **REST API для продажів** (дані тримати **в пам'яті**, БД у цьому ПЗ НЕ використовуємо):
   - `POST /sales` — додати продаж (менеджер, товар, сума, дата, регіон).
   - `GET /sales` — список (з фільтром за регіоном/періодом).
   - Валідація вхідних даних + обробка помилок (правильні HTTP-коди).
2. **Генерація PDF-звіту** `GET /reports/sales.pdf?month=2026-09`:
   - Заголовок, період, таблиця продажів.
   - **Підсумки**: загальна сума, розбивка **по регіонах** і **по менеджерах** (топ-продавці).
   - Гарне оформлення (шрифт із підтримкою **кирилиці** — окрема пастка, гугли!).
3. **Email-розсилка** `POST /reports/send?month=2026-09`:
   - Згенерувати PDF і надіслати його **вкладенням** на список отримувачів.
4. **Планувальник**: `@Scheduled` — 1-го числа кожного місяця автоматично сформувати й розіслати звіт за попередній місяць.

## Куди підключатись / що використати (гуглити!)

- **PDF-бібліотека** — на вибір: **OpenPDF** (форк iText, вільна ліцензія) або **Apache PDFBox**, або HTML→PDF через **openhtmltopdf** + **Thymeleaf**-шаблон. Обрати й обґрунтувати.
- **Кирилиця в PDF** — стандартні шрифти iText/PDFBox її НЕ малюють. Треба **підключити TTF-шрифт** (напр. DejaVu Sans / Liberation). Це головна технічна пастка завдання.
- **Email із вкладенням** — `spring-boot-starter-mail`, `MimeMessageHelper.addAttachment(...)`.
- **Дані** — сховище в пам'яті (`ConcurrentHashMap`/`List`), **без JPA**.

## Критерії оцінювання

| Рівень | Бал | Що це означає |
|--------|-----|----------------|
| **Повністю + тести** | **25** | Усі 4 пункти працюють; PDF гарний, з кирилицею й коректними підсумками; email із вкладенням приходить; cron налаштований; є тести |
| **Повністю без тестів** | **21** | Усе працює end-to-end, тестів немає/формальні |
| **Частково** | **17** | PDF генерується й надсилається, але є суттєвий недолік: немає розбивки по регіонах/менеджерах, або кирилиця «квадратиками», або немає cron |
| **Половина** | **12** | Є REST API + PDF генерується (можна відкрити), але email/розсилка не працює |
| **Базове** | **7** | Працює лише REST API продажів (POST/GET + валідація), PDF не готовий |
| **Не працює / не здано** | **0** | Не компілюється або відсутнє |

### Штрафи

- **−3** — кирилиця в PDF відображається «квадратиками» (не підключено TTF-шрифт), хоча решта готова.
- **−2** — немає поділу на шари (усе в контролері).
- **−2** — секрети SMTP у git.

### Бонус (не вище 25)

- **+2** — графік/діаграма в PDF (стовпчики по регіонах).
- **+2** — параметр звіту: період довільний (`from`/`to`), а не лише місяць.
- **+1** — генерація ще й у форматі Excel (`.xlsx`) поряд із PDF.

## Definition of Done

- [ ] `POST /sales` і `GET /sales` працюють, дані валідуються, помилки — коректні коди.
- [ ] `GET /reports/sales.pdf?month=...` віддає **валідний PDF** з таблицею й підсумками.
- [ ] Кирилиця в PDF відображається **коректно** (підключено TTF-шрифт).
- [ ] `POST /reports/send` надсилає PDF **вкладенням** на список email.
- [ ] `@Scheduled` щомісячної розсилки налаштований.
- [ ] Код поділено на шари; секрети не в git; `mvn test` зелений.
