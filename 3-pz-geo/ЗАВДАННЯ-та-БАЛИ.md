# ПЗ-3. Гео-сервіс «Точки на карті» з базою даних

> **Тип:** практичне заняття (4 пари, 8 годин) — **фінальне завдання курсу**.
> **Максимальний бал:** **35**.
> **Повна інструкція з реалізації:** див. [`pz-3-geo.md`](./pz-3-geo.md).
> Цей файл — лише **умова** й **бали**.
>
> ⚠️ **НЕЗАЛЕЖНЕ завдання** — не продовжує ПЗ-1/ПЗ-2. Новий проєкт з нуля.
> Використовує **БД (Spring Data JPA)** з Лекції 2 + інтеграцію із зовнішнім гео-API.
> Багато чого треба **загуглити**: як звертатись до OpenStreetMap, як рахувати відстань між координатами.

## Легенда

Ти робиш бекенд для застосунку «**Мої місця**»: користувач зберігає цікаві локації
(кафе, memorial, друг живе тут…) за **адресою**, а сервіс сам знаходить **координати**,
зберігає їх у БД і вміє відповідати на запити типу «які мої місця в радіусі 5 км від точки».

## Умова — що потрібно зробити

1. **CRUD місць** через REST + **БД** (`@Entity Place`: назва, адреса, категорія, широта, довгота).
2. **Геокодування адреси → координати** через зовнішній API **Nominatim (OpenStreetMap)**:
   при створенні місця за адресою сервіс сам підтягує `lat/lon` і зберігає в БД.
   (Ключ **не потрібен**, але є **правила чемного використання** — див. інструкцію.)
3. **Пошук поблизу** `GET /places/nearby?lat=..&lon=..&radiusKm=5` — повернути місця в радіусі,
   відсортовані за відстанню (**формула Haversine** — гугли).
4. **Категорії та фільтри**: список за категорією, пошук за частиною назви, **пагінація**.
5. **Кешування геокодування**: та сама адреса не має ходити в зовнішній API двічі
   (кеш у БД або Spring Cache).
6. **Стійкість до збоїв API**: якщо Nominatim недоступний/не знайшов адресу — коректна помилка,
   а не 500 (місце можна зберегти без координат і догеокодувати пізніше).

## Куди підключатись / що використати (гуглити!)

- **Nominatim (OpenStreetMap)** — `https://nominatim.openstreetmap.org/search?q=...&format=json`.
  Обов'язково **свій `User-Agent`** (правило Nominatim) і **не частіше 1 запиту/сек**.
- **HTTP-клієнт** — `RestClient` (Spring 6.1+) або `WebClient`/`RestTemplate`. Обрати й обґрунтувати.
- **БД** — H2 для розробки, **PostgreSQL** для «прод»-режиму (docker-compose). Spring Data JPA.
- **Haversine** — формула відстані між двома точками по координатах (реалізувати самостійно).

| **Ядро** | **20** | CRUD у БД + геокодування працюють, але **пошук поблизу відсутній/некоректний** (не рахує відстань) |
| **Половина** | **14** | CRUD місць у БД працює, але інтеграції з Nominatim немає (координати вводяться руками) |
| **Базове** | **8** | Проєкт піднімається з JPA, є `@Entity` і репозиторій, але CRUD неповний або без валідації/помилок |
| **Не працює / не здано** | **0** | Не компілюється або відсутнє |

### Штрафи

- **−3** — немає власного `User-Agent` для Nominatim (порушення правил сервісу) або запити без обмеження частоти.
- **−3** — падіння з 500, коли Nominatim недоступний або адресу не знайдено (немає обробки).
- **−2** — Haversine реалізовано в контролері (немає поділу на шари).
- **−2** — N+1 або тягнеться вся таблиця в пам'ять для пошуку поблизу без потреби.

### Бонус (не вище 35)

- **+3** — reverse-геокодування (координати → адреса) окремим ендпоінтом.
- **+2** — фільтр пошуку поблизу ще й за категорією («кафе в радіусі 3 км»).
- **+2** — простий HTML/JSON-ендпоінт, що віддає GeoJSON для відображення на карті (Leaflet).
- **+2** — міграції схеми через Flyway замість `ddl-auto`.
